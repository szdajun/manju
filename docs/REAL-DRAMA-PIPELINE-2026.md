# 真人短剧管线可行性方案（2026-08-06）

> 背景：用户拍板"漫剧不讨好"，转向**真人短剧**。manju 现有 ep03 写实短剧雏形（23.62s 已验证）。
> 目标：做出自己的 **AI 真人短剧创作管线**（题材 → 剧本 → 分镜 → 导演台 → 生成 → 成片）。

---

## 一、市场可行性（2026 上半年数据）

### 1.1 市场在爆发，方向验证正确
- **AI 仿真人短剧占 AI 剧 70%+**（6 月），2D/3D 漫剧不足 28% → **市场已转向真人**，印证"漫剧不讨好"。
- AI 短剧半年规模 **220 亿元**，全年有望 400 亿（同比增长 138%）；用户突破 6 亿。
- 抖音上半年新增 AI 短剧 **22.19 万部**，1055 部破亿播放；全网首部播放超 20 亿的 AI 剧已出现。
- 制作成本雪崩：真人精品短剧 150 万 → AI 拟真人 **20 万内**（个别 2-3 万）。

### 1.2 两个残酷现实（决定定位）
1. **爆款率极低**：AI 短剧爆款率仅 **0.47%**，AI 漫剧不足 0.1% → "内容，内容，还是内容"。产能不是壁垒（"一人一天一部剧"已成现实），**创意/资产/完整工具链**才是。
2. **成本没真正降**：流量占全链路 70%；千次播放收益从 60 元跌到 **15-30 元**；平台分成收紧（抖音仿真人 60%→40%，红果取消保底）。

### 1.3 入局判断（对我们的意义）
- **机会**：技术门槛被拉平 → **能做出完整工具链 = 竞争力**。对标 AniShort（日产 40 部、119 元/分钟）/ Kino视界（四大 AI Agent + 3D 导演台）。
- **风险**：单靠"生成视频"已不赚钱（分成下滑），**内容质量 + 资产沉淀 + 出海**才是方向。
- **对我们**：不求追爆款（0.47% 概率），**做差异化工具管线**（贴合健身/品牌 IP 的幽默真人短剧），成本可控（Seedance 480p ¥0.39/镜）。

### 2.2 核心缺口（量产前必须解决）
| 缺口 | 严重度 | 说明 |
|------|--------|------|
| **衣服跨镜一致性** | **极高** | 双 IPAdapter 只部分锁衣（雾蓝 5/5、白弧 logo 0/5）。LoRA 锁大件锁不了小标志。**这是用户第一痛点** |
| **唇同步未集成** | 高 | MuseTalk 仅 ep02 WSL 跑通，未进标准管线 |
| **一键出片 orchestrator** | 高 | 各阶段脚本分散，手动串 |
| **剧本自动生成** | 中 | 纯手工写 Python 模块 |
| **BGM/调色/角标** | 中 | 完全缺失 |
| **写实男角 LoRA** | 中 | 李辉训了但 caption 错误需重做 |

### 2.3 关键坑（记牢）
- Seedance 2.0 **真脸禁** → 1.0 pro 是唯一无禁令选项
- LTX-2.3 本地 **无 I2V 节点**（仅 T2V），双人不稳
- 本地 Wan2.2 被 torch bug 卡死，弃
- 所有 ID-embedding 方案**只锁脸不锁身**（IPAdapter/PuLID/InstantID 结构性缺口）

## 三、目标管线设计（用户要的功能）

对照 AniShort / Kino视界，设计我们的**真人短剧创作管线**，7 大模块：

```
┌────────────────────────────────────────────────────────────┐
│  AI 真人短剧创作管线 (manju v2)                              │
├────────────────────────────────────────────────────────────┤
│  ① 题材库    题材分类 + 热门题材雷达 + 题材卡片（健身/生活/幽默）│
│  ② 剧本引擎  LLM 生成剧本 → 结构化剧情（幕/场/镜）+ 台词       │
│  ③ 分镜工具  剧本 → 分镜表（景别/机位/时长/情绪）+ 分镜图生成   │
│  ④ 导演台    角色站位/机位/灯光可视化 + 关键帧参考图生成       │
│  ⑤ 生成链    关键帧生图 → i2v → 配音 → 唇同步 → 字幕          │
│  ⑥ 后处理    调色/角标/BGM/拼接/导出 竖屏三件套               │
│  ⑦ 资产库    角色立绘/LoRA/服装指纹/场景库（跨集复用）          │
└────────────────────────────────────────────────────────────┘
```

### 关键设计决策

**① 题材库**
- 健身题材（贴合现有 IP/角色资产），幽默向（延续"打工牛马"调性）
- 题材卡片 = 结构化模板（角色设定 + 冲突 + 反转 + 目标观众）

**② 剧本引擎（LLM）**
- 接入点已有：豆包 `doubao-seed-1.6`（ARK key，唯一可用文本 LLM，支持 CoT）
- 生成结构化剧情 JSON（幕/场/镜 + 台词 + 情绪 + 镜头语言）→ 直接喂分镜

**③ 分镜工具**
- 剧本 JSON → 分镜表（复用 ep03 的 SHOTS/LINES/I2V_MOTION 约定）
- 分镜图一键生成（ComfyUI 关键帧批量）

**④ 导演台（对标 AniShort 3D 导演台 / Kino L3）**
- MVP：2D 关键帧构图预览（角色位置/景别/机位参数化）
- 进阶：3D 场景站位调整 → 参考图（对标 AniShort"抽卡率降 90%"）

**⑤ 生成链**
- 复用现有：ComfyUI 生图 + Seedance i2v + MiniMax TTS + ffmpeg 组装
- **衣服一致性**：双 IPAdapter（face 0.95 + body 0.70）+ 角色 LoRA + 服装指纹 prompt 不变式
- 唇同步：集成 MuseTalk（需解 WSL 依赖）

**⑥ 后处理**
- 补：调色 LUT / 角标水印 / BGM（ep05 有 beat_extract 基建）

**⑦ 资产库**
- 角色立绘 + LoRA + 服装指纹 → 跨集复用（对标 Kino"双主体资产库"）

## 四、落地路径（分阶段）

### Phase 1：管线 MVP（先把现有资产串成一键）
- **目标**：ep03 真人短剧从"手动串 5 步"变成"一键出片"
- **内容**：
  1. **Orchestrator**：`manju run_ep --ep XX` 一键跑通（剧本→生图→i2v→配音→组装）
  2. **剧本 LLM**：豆包生成结构化剧本 JSON → 分镜表
  3. **分镜工具**：剧本 JSON → SHOTS/LINES/I2V_MOTION 自动生成
- **交付**：一条命令产出一集真人短剧（复用 ep03 全部资产）

### Phase 2：导演台 + 资产库
- **内容**：
  1. **导演台 MVP**：关键帧构图预览（角色位置/景别参数化）
  2. **资产库**：角色/服装/场景复用（跨集一致性核心）
  3. **衣服一致性强化**：服装指纹库 + 双 IPAdapter 调参 + LoRA 迭代
- **交付**：可复用角色的多集产出能力

### Phase 3：工业化（对标 AniShort/Kino）
- **内容**：
  1. 唇同步集成（解 WSL）
  2. 调色/角标/BGM 补全
  3. 题材雷达 + 批量生产流水线
  4. （可选）出海多语言
